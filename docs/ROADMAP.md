# Roadmap and task queue

T01 to T08 are done, and the first supervisor meeting changed what comes next ([meeting notes](meetings/2026-11-supervisor-meeting-1.md), [ADR 0021](decisions/0021-guided-sketching-and-user-study.md)). The primary objective is now a system that supports a user study of guided sketching, added as T09 to T11 below. Task completion is recorded in [STATUS.md](STATUS.md). Timeframes count months from the start of development and are planning estimates, not deadlines.

Development is incremental. From T01b on, every task ends with a runnable increment of the same program that the owner can try, and each task upgrades it rather than starting something new. The program runs as the `sketchloop` command, installed by `pyproject.toml` as a console script starting in T01b.

## Order of work after the supervisor meeting

The [first supervisor meeting](meetings/2026-11-supervisor-meeting-1.md) made a user study the primary objective ([ADR 0021](decisions/0021-guided-sketching-and-user-study.md), requirements S01 to S05 in [PROJECT.md](PROJECT.md)). The submission target is in early 2027, so T09, T10, and T11 come first, in that order. The T07 and T08 refinements, including a modularity validation, come before T09, and T12 documents the project at the end. U1 records and U2 wait until the 40 drawings are collected.

If the project becomes a thesis, the study extends to professional artists: 40 more drawings from experts, compared directly with those of inexperienced participants. It needs no new features beyond T10 and is not scheduled until the follow-up meeting decides it.

## UI session requirements

Requirements the owner set while using the page. They are repository decisions, not proposal requirements, and each gets its own bounded task.

| ID | Requirement | Decision | Status |
| --- | --- | --- | --- |
| U1 | The page suggests style prompts based on the sketch, fully offline, with no cloud model, API key, or network. A fixed list of style suggestions is always available, and one small local vision model looks at the sketch to propose full prompts. Suggestions only fill the prompt box, and the person still edits and triggers generation. | [ADR 0019](decisions/0019-offline-prompt-suggestions.md), [research note](research/prompt-suggestion-models.md) | Implemented and tested offline. Florence-2-base names the sketched object and fills five style templates, and the fake backend uses the templates alone. A suggestion is written only when the person presses "Suggest a prompt", and pressing again for the same drawing gives the next style. Suggestion records are not saved yet and are scheduled after the user study. |
| U2 | The person can continue the next round from a selected candidate. A "Continue from this candidate" action runs ControlNet image-to-image, with the candidate as the starting image, the current sketch still steering the shape, and a strength slider from light touch-up to free reimagining. A "same seed" option reuses the candidate's seed instead, with the sketch as the only input. The physical sketch is never replaced silently. | [ADR 0020](decisions/0020-continue-from-a-candidate.md) | Proposed, scheduled after the user study |
| U3 | The page offers the backend's generation controls, starting with the number of steps, and also guidance and conditioning scale, built from the backend's capabilities with each mode's defaults and limits. The chosen values are recorded as requested controls, as `run` already does. | Uses the existing controls in the generator contract ([ADR 0009](decisions/0009-diffusers-backend.md)) | Implemented and tested offline. One slider per numeric control, in rows of two, with steps starting at 10 on the page in either mode. |
| U4 | The page is simpler to use with the real model. The settings sit under Generate, always visible. The webcam starts streaming by itself on load and whenever it is shown again. "Sketch the model will receive" shows the newest webcam frame, preprocessed unless raw, every capture interval. The seed field is blank for random, a whole number from 0 to 2147483647 otherwise. The page starts at 1 candidate per round. Labels are short and have no parentheses, and rotation and the raw option sit under the sketch. | Page changes over the existing controller ([ADR 0012](decisions/0012-gradio-ui-and-input-source.md)) | Implemented. Webcam start and the 0.5 s preview were checked in headless Chrome with a fake camera, and the rest with offline tests only. |
