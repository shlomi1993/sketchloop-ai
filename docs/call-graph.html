sketchloop-ai · state after T07

How the browser page reaches the model and the disk

SketchLoop turns a pencil sketch on paper into AI alternatives. A webcam sees the paper, Stable Diffusion 1.5 with ControlNet scribble draws candidates in the prompt's style, the person explicitly picks some, and every round is saved so it can be shown and rerun later.

The code is layered so that each layer only calls the one below it. The browser page talks to AppController, which owns one SketchSession. The session runs each round through four replaceable abstract base classes. A settings file decides which subclass sits behind each one.

3 · One round, step by step

  1. The browser streams webcam frames, and keep_frame keeps only the newest one, converted to OpenCV's BGR order, with the time it arrived. Generate becomes clickable once there is a sketch and a non-blank prompt.
  2. run_generation takes that frame and its age, refusing it once the stream has stopped sending frames, or takes the uploaded file path, and calls AppController.run_round. All session-changing handlers share one concurrency group, so a choice cannot interleave with a running round.
  3. AppController checks the sketch, prompt, and rotation before writing anything, then turns the input into an ImageRef and bytes with encode_frame or load_sketch_file.
  4. SketchSession.run_round saves session.json once, with the hardware and the generator setup time, preprocesses the sketch unless raw is ticked, builds a GenerationRequest, and calls the generator, which validates the request against its capabilities first. The new iteration is linked to the previous round's ID, then the evaluator scores the candidates. Each stage is timed: capture, preprocessing, model load on the first round, generation, evaluation, and saving, plus the round's total and, for a webcam round, the frame's age.
  5. The store writes the raw sketch, the processed sketch, the candidates, and round.json. If any stage fails, saving included, a failed record naming the stage joins the history and is saved when the store allows, and the stage's own error reaches the page as a one-line message.
  6. AppController turns the outcome into a RoundView with image paths, captions, the fake-backend flag, and the iteration ID, and ui.py renders the gallery and checkboxes.
  7. Record my choice sends back the iteration ID the page showed. AppController refuses an older round or a second choice, domain.py builds the SelectionEvent, and the session rewrites round.json with it.

5 · Rules the wiring enforces

  • Swapping a component means adding a registry entry in components.py or backends/__init__.py and naming it in settings. The session and UI do not change.
  • Human choice stays explicit. Ticking nothing is recorded as an explicit choice of none, and scores never select anything.
  • A failed round stays visible as failed, with the stage it failed in, and never overwrites an earlier round.
  • Fake output is labeled on every caption and status line, so it cannot be mistaken for model output.
  • Selections must name the iteration the page showed, which protects against a stale browser tab.
