# Experiment records and reproducibility

Status: proposed implementation contract derived from R06; exact serialization is decided during T01/T05. This document adds engineering detail to the source requirement and does not describe an implemented store. The first in-memory records for guidance, generation, candidates, iterations, and selection are specified in [the T01a design](design/t01a-contracts.md).

The proposed on-disk records (`session.json` and `round.json`), loading checks, and the `show` and `rerun` subcommands are specified in [the T05 design](design/t05-records.md) and [ADR 0011](decisions/0011-session-records-and-subcommands.md), which was accepted and implemented in T05. [ADR 0012](decisions/0012-gradio-ui-and-input-source.md), implemented in T06, adds `input.source` to `round.json`, naming whether the raw sketch came from a file, the host camera, a browser webcam, or a browser upload. Older records load it as unavailable, without a schema version bump. [The T07 design](design/t07-modularity.md) and [ADR 0014](decisions/0014-replaceable-components-and-settings.md), implemented in T07, move the writes behind an `ExperimentStore` protocol that raises `StoreError` when a save fails, without changing the record format or schema version. The folder store remains the only persistent store, and `show` and `rerun` read only folders. An in-memory store exists for tests and is not selectable in settings.

## Minimum information

| Record | Fields to preserve |
| --- | --- |
| Experiment | Schema version, opaque experiment ID, creation time, research configuration, environment/dependency snapshot including the sketchloop-ai version |
| Iteration | Opaque iteration ID, parent iteration ID or null, attempt/retry relationship, status, start/end time, stage durations and units |
| Capture | Raw image artifact reference and checksum, capture timestamp, non-identifying acquisition settings, sketch version |
| Processing | Processed artifacts/checksums, ordered operation names/versions, effective parameters, crop/perspective transforms when used |
| Guidance | Prompt, negative prompt when supported, style/functional descriptions, reference/conditioning artifact references, validated requested controls |
| Generation | Adapter/version, model identity and revision, effective settings and defaults, seed(s) when supported, scheduler/steps/strength where applicable, device/runtime details relevant to reproducibility |
| Candidates | Stable IDs, output artifact references/checksums, per-candidate generation metadata |
| Evaluation | Evaluator identity/version/configuration, scores and meaning, filter decisions, or explicit absence of evaluation |
| Selection | Selected candidate IDs or explicit no-selection, iteration link, event time; separate from automated ranking |
| Failure | Failed stage, sanitized error category, completion state, retained partial artifacts; no credentials or raw private paths |

Record unavailable values as unavailable with a reason; do not fabricate seeds, versions, or timings. Requested configuration and effective configuration can differ and must remain distinguishable. Capture only environment details that matter; omit usernames, machine names, home directories, and credentials.

## Persistence behavior

Keep raw input and all generated alternatives, including filtered ones, so later analysis is possible. Do not overwrite artifacts on retry. Use stable relative artifact paths within an experiment directory; reject path traversal when loading manifests. Validate schema and checksums. Commit metadata atomically after artifact writes, and distinguish pending, complete, failed, and cancelled states as needed by the implementation. Define migrations before changing a persisted schema.

Default local artifacts belong under ignored `runs/`; exports must be deliberately sanitized before being copied into a public directory. Synthetic test fixtures are the only default public experiment examples.

## Three distinct operations

1. **Inspect:** load saved inputs, outputs, parameters, timings, scores, selections, and history without invoking a model.
2. **Reconstruct:** validate stored artifacts and recover effective configuration and model prerequisites. Report unavailable dependencies or model versions before running.
3. **Rerun:** generate a new linked attempt from reconstructed conditions. Record any differences and determinism limits; preserve the original record.

Restoring conditions is required. Bit-for-bit regeneration is not universally guaranteed across hardware, kernels, remote providers, or model revisions. Seeds alone are not a reproducibility guarantee. Test exact output equality with the deterministic fake adapter; characterize the real backend honestly.

## Evaluation plan

Use synthetic or authorized sketches to exercise capture/preprocessing, multiple candidates, selection, revised input and a second iteration, save/load, and rerun. Test missing/corrupt artifacts, unsupported controls, failed generation, interrupted persistence, and invalid lineage. Separate camera/model integration tests from default offline checks.

Measure capture, processing, generation, evaluation, persistence, and total response time. State image size, batch size, configuration, hardware/runtime, warm-up treatment, number of runs, and distribution, for example median and p95. The brief gives no fixed latency threshold. Establish a measured baseline before setting targets or claiming real-time behavior.

[The T08 design](design/t08-latency.md) and [ADR 0017](decisions/0017-stage-timings-hardware-and-benchmark.md), implemented in T08, specify how this is recorded within schema version 1. Each round times `capture`, `preprocessing`, `model_load`, `generation`, `evaluation`, and `saving` in `timings_seconds`, plus a `total_seconds` field. `model_load` adds the backend's reported load to the time an evaluator takes to load before its first scoring. `session.json` adds `environment.hardware` with the CPU model name, logical cores, and total memory, the generator setup time before round 1, and a `benchmark` plan with warm-up and measured round counts. A round from a streamed webcam frame also records `input.frame_age_seconds`. Older records load the new values as unavailable with a reason. `sketchloop benchmark` reports median, p95, min, and max per stage over the measured rounds, with warm-up rounds shown separately.

Human interpretation and automated similarity measure different things. Record score semantics; do not use CLIP similarity as a universal design-quality score. Each completed round records `evaluation.evaluator` (the class name), `evaluation.scores` by candidate ID, and `evaluation.score_details`, which the evaluator fills with the model, its pinned revision, and what the score means. The CLIP evaluators record a cosine similarity from -1 to 1 between the candidate image and the prompt cut to 77 tokens. Rounds written before `score_details` existed load it as empty, which matches the no-op evaluator they used, and the schema stays at version 1. Model comparisons remain optional extensions. The user study in [ADR 0021](decisions/0021-guided-sketching-and-user-study.md) adds suggestion events, a drawing timeline, inferred acceptance, and study metadata to the records within schema version 1, designed in T09 and T10 of [ROADMAP.md](ROADMAP.md). [The T09 design](design/t09-guided-sketching.md) and [ADR 0025](decisions/0025-drawings-as-the-unit-of-guided-sketching.md), both accepted, put them in a new `drawing-<n>/drawing.json` beside the rounds in a session folder named by the experiment name the experimenter enters, such as `runs/participant1_car/`, holding every capture with its alignment and per-part scores, every suggestion with its request, effective settings, model identity, parts, window, and decision, and the final capture. Older sessions load with no drawings.

Implemented so far, within schema version 1:

- **Experiment names:** `session.json` has an optional `name` after `session_id`, equal to the folder name and null for time-named and older sessions. A name is 1 to 64 ASCII letters, digits, `_`, or `-`, starts with a letter or digit, and is not a Windows device name. The store claims the folder before anything is saved and refuses a name equal, ignoring case, to any entry of the runs folder.
- **Drawing records:** `drawing.json` holds the drawing number and ID, start and end times, how it ended, the canvas size, the capture interval, `interval_jpeg_quality`, whether suggestions are on and which suggester class ran, the follow method with its version and every threshold (`follow_detector`, null with suggestions off), the captures, the suggestions, and the final capture. Each capture records its trigger, wall-clock time, seconds since the drawing started, source, frame age, rotation, raw frame, canvas, `filled` mask, canvas steps, stage timings, any canvas failure, and `follow` when a suggestion was open. Each suggestion records its status, request with the prompt exactly as typed, the suggester's result with each part's overlay color, the overlay, stage timings, and any failure with its stage. A suggestion with no parts is shown and recorded like any other.
- **Captures:** an interval capture is saved at most once per 0.8 of `drawing.save_interval_seconds`, 2 s by default, while a drawing is open, with its raw frame as JPEG at the quality recorded as `interval_jpeg_quality`, now 90. An interval capture that arrives while a suggestion is running is skipped rather than saved late with a stale frame. The frames at each suggestion press and at finish stay PNG, and an uploaded JPEG is kept as received, so its quality is unknown. Every capture keeps its paper-frame canvas as PNG and, as `captures/capture-<n>-filled.png`, a mask that is 255 where the canvas was filled with the paper's level rather than seen, such as outside the sheet or under a hand reaching in from the frame edge. A capture's timings add `scoring` when it was aligned and, for an interval capture, `saving`, which reaches `drawing.json` with the next save.
- **Alignment:** every capture taken while a suggestion is open records `follow` with the suggestion's number, the seconds since it was shown, `alignment`, `new_stroke_pixels`, and `parts`. The alignment holds whether ECC converged, its correlation or the reason it did not converge, the 3x3 homography from capture to baseline pixels, and the share of the capture's canvas hidden as an occluder, such as a hand, or as a filled area. It is found with ECC homography on lighting-independent darkness maps, hiding occluders and filled areas in both canvases. A converged warp is refused as not converged, with the correlation and corner shift in the reason, when its correlation is under `min_ecc_correlation` (0.4) or it moves a canvas corner more than `max_corner_shift_pixels` (32). `new_stroke_pixels` counts strokes in the aligned capture away from the baseline's strokes and hidden pixels, and is null when alignment failed. A failed alignment is recorded, never raised. Drawings saved before alignment load with no `follow` and no `follow_detector`.
- **Part scores:** `parts` has one entry per part of the open suggestion, in index order, and is empty when alignment failed. Each holds `part`, `occluded_share` (the share of the part's mask that is hidden), `new_pixels_near` (new-stroke pixels in the part's box grown by 32 px), `coverage` and `precision` keyed by the tolerances 4, 8, 16, and 24 px, and `chamfer_part_to_new` and `chamfer_new_to_part`, mean distances capped at 64 px. Coverage is the share of the part's visible skeleton within the tolerance of a new stroke, and is unavailable when the whole part is hidden. Precision is the share of the new strokes near the part that lie within the tolerance of its mask, and is unavailable, as is `chamfer_new_to_part`, when no new strokes are near. `chamfer_part_to_new` is unavailable when the part is hidden or nothing new was drawn. Values are rounded to 4 decimals. Following ADR 0024, a different shape drawn in the part's place counts as covering it. The scores are research signals for the rule in a later slice, not decisions. Captures saved before part scores load with `parts` null, before filled masks with `filled` null, and drawings before the quality was recorded with `interval_jpeg_quality` unavailable.
- **Writing:** files are written first and `drawing.json` is rewritten atomically after each press and at finish. Files from a failed save are sent again with the next save, so the record never names a file that was not written. A suggestion's saving time reaches `drawing.json` with the drawing's next save.
- **Loading:** `load_session` reads `drawing-<n>` folders with the same gap check as rounds, verifies every recorded image, and lists a changed file or a folder without `drawing.json` as a problem.
- **Not yet recorded:** suggestion windows, decisions, and the rule, which a later T09 slice adds. Participant data stays in ignored local storage under pseudonymous codes, as [PRIVACY.md](PRIVACY.md) requires.
